The judge-visible loop

The final ETHOnline path will make every sponsor load-bearing in one workflow. Until the sponsor credentials and testnet contracts are configured, the page deliberately labels those steps as DESIGN.

02 · PLANTreasuryPlanner proposes

04 · AUTHORIZEPrivy wallet control
05 · ESCROWArc USDC task
06 · VERIFYIndependent verifier
07 · RECEIPTHash + explorer proof

Three outcomes

VERIFIED

Release after proof

Seller output passes the independent checks, so the escrow becomes eligible for release.

resultHash → verifier decision → settlement receipt
BLOCKED

Stop before execution

Budget, permission, risk or confirmation fails. No seller execution and no payment release.

policy failure → no write → reason code
FROZEN

Contain bad output

The task executed, but the output does not satisfy the verifier. Funds remain isolated pending recovery.

mismatch → frozen escrow → recovery boundary
